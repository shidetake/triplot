# ログイン方法（Google と Apple）

1つのアカウントに、Google と Apple の両方のログイン方法を付けられる。どちらで
ログインしても同じアカウントに入り、同じ旅行が見える。

## どのアカウントにつながるか

| 状況 | 結果 |
|---|---|
| Google と Apple のメールアドレスが同じ | ログインの仕組み（Supabase）が自動で同じアカウントにまとめる |
| Apple で「メールを非公開」を選んだ・そもそも違うメールアドレス | 別のアカウントになる |
| 設定の「ログイン方法」で追加した | 今のアカウントに付く |

## 追加はするが、アカウントの統合はしない

設定の「ログイン方法」は、今のアカウントに**まだどのアカウントにも使われていない**
Google / Apple を足すだけ。その Google / Apple で既に別のアカウントがある場合は
Supabase が追加を断るので、案内を出して終わる:

> この Apple は別のアカウントで使われています。そのアカウントが不要なら、Apple で
> ログインしてアカウントを削除してから、もう一度追加してください。

統合（片方の中身をもう片方へ移して片方を消す）をしない理由:

- うっかりできた2つ目のアカウントは、たいてい空。「削除してから追加」で本人が直せる。
- 統合には、消える側のログイン方法の付け直し、両方のアカウントへのログインを
  行き来する画面、メールの転送先アドレスが1つ消える問題がある。手間に見合わない。
- 両方に中身がある人は個別に対応する。同じ相談が続くようなら統合を検討する。
  その時は、ゲストの本登録の引換券方式（下記）を普通のアカウント同士に広げ、
  追加はそのまま土台に使う。

## ゲストの本登録は引換券方式のまま

ゲストの本登録は「追加」を使わず、引換券方式（ゲストのうちに引換券をもらい、
ログインした後で引き換えてゲストの中身を移す）で行う。

既にアカウントを持っている人がゲストで参加して費用などを入れていた場合、
「追加」では断るしかなく、同じ旅行に同じ人が2人いる状態（精算が割れる）になる。
引換券方式はこれを中身ごと移して片付けられる。

## 前提と注意

- Supabase の設定「手動での連携」（Manual linking）が有効であること。
- iOS は、Google / Apple から受け取った本人確認の証明を渡して追加する
  （web はログインと同じリダイレクト）。Supabase のログイン部品は 2.110.0 で
  この形に対応している。ゲストの本登録の migration のコメントにある
  「iOS と噛み合わない」は、この版では当てはまらない。
